# Альфа tasks

Мобильный лендинг в формате Telegram Mini App: проверка участия, витрина заданий, выбор уровня награды, пошаговая инструкция и личный кабинет с заданиями в процессе.

**Рабочий URL:** https://alfa-w3ll.onrender.com

## Почему сайт «не открывался»

Настоящая причина была не в хостинге, а в коде: в `app.js` (строка 44, функция `renderActiveTask`)
**не была закрыта шаблонная строка** — пропущена обратная кавычка перед `;}`.

Из-за этого браузер не мог разобрать модуль целиком:

```
SyntaxError: Unexpected token 'class'   (app.js:45)
```

`app.js` подключён как `<script type="module">`, поэтому при ошибке разбора не выполняется
**ничего** — `<div id="app">` остаётся пустым, и пользователь видит пустой белый экран
в Telegram и в обычном браузере. Ошибка не видна без консоли разработчика, поэтому выглядело,
будто «сайт не работает».

Проверить одной командой:

```bash
node --check app.js
```

## Что исправлено

1. **Закрыта шаблонная строка в `renderActiveTask`** — приложение снова разбирается и рендерится.
2. **Версия кэш-бастинга поднята до `?v=20260917-9`.** Это обязательно: `app.js` отдаётся с
   `Cache-Control: immutable, max-age=31536000`, поэтому у тех, кто уже открывал сайт,
   сломанный файл лежит в кэше на год. Новый URL заставляет его скачать заново.
3. **Страховка от белого экрана** (двухуровневая):
   - `index.html` — watchdog: если `app.js` не загрузился или упал при разборе, вместо пустой
     страницы показывается понятное сообщение с кнопкой «Обновить страницу»;
   - `app.js` — `render()` обёрнут в `try/catch`, при сбое рисуется аварийный экран с текстом ошибки;
   - добавлен `<noscript>`-вариант страницы.
4. **Устойчивость к злому окружению:** обращение к `localStorage` при инициализации больше не
   может уронить приложение (в некоторых WebView хранилище заблокировано и бросает `SecurityError`),
   тост не падает при отсутствии элемента.
5. **Имя пользователя в шапке** теперь полное (`getDisplayName`), как в карточке профиля —
   раньше в шапке было только имя, и через ~250 мс текст «прыгал» на полное имя.
6. **`render.yaml`:** добавлено правило `Cache-Control: no-cache` для корневого пути `/`
   (запрос к главной идёт как `/`, а не `/index.html`) — иначе `index.html` может закэшироваться,
   и пользователи останутся на старых ссылках `?v=…`.
7. **Удалён пустой файл `.github/workflows/keep-alive.yml`** (0 байт — GitHub считает такой
   workflow невалидным) и добавлен нормальный CI.

## Пошаговая инструкция и сдача задания (обновление от 17.09.2026)

Тексты двух инструкций и логика сдачи отзыва лежат в `app.js`. Версия кэш-бастинга поднята
до `?v=20260917-11`.

**Вариант 01 — дебетовая карта (награда до 2 000 ₽).** Инструкция из 5 шагов:

1. Оформи дебетовую карту Альфа-Банк по ссылке
2. Прими доставку продукта в удобное время
3. Активируй карту, совершив любую покупку этой картой от 1 рубля (переводы не считаются)
4. После этого зайди в личный кабинет и напиши отзыв под заданием
5. Готово! В течение 3-4 дней награда поступит на вашу карту

Внизу — блок `P.S. ЕСЛИ ТЕБЕ МЕНЬШЕ 18, ТО ПОТРЕБУЕТСЯ ЭЛЕКТРОННОЕ ПОДТВЕРЖДЕНИЕ ОТ РОДИТЕЛЯ`
(только у этого варианта).

**Вариант 02 — кредитная карта (награда до 4 000 ₽, 18+).** Те же 5 шагов, первый — «Оформи
кредитную карту Альфа-Банк по ссылке». Блока `P.S.` нет.

Тексты шагов хранятся в объекте `instructionPlans` (`small` — вариант 01, `large` — вариант 02),
и рендерятся через `renderInstructions()`. Чтобы поменять формулировку, правится только массив
`steps` / строка `note` — вёрстка (`ol.step-list`, `li.step-item`, `.step-note`) собирается сама.

### Как теперь работает сдача задания в личном кабинете

Задание в разделе «Задания в процессе» получило кнопку **«Выполнил»** и пошаговый диалог:

1. **«Выполнил»** → модальное окно с вопросом «Ты получил карту и совершил с ней покупку?»
   и вариантами **«Да, всё выполнено»** / **«Нет, ещё нет»**.
2. **Нет** → окно «Нужно дождаться выполнения условий»: объяснение, что карта должна быть
   оформлена по ссылке, доставлена и активирована покупкой от 1 ₽, ссылка «Оформить карту»
   и кнопка «Понятно, продолжу позже». Задание остаётся в статусе «В процессе».
3. **Да** → окно «Напиши отзыв под заданием» с полем ввода (10–1200 символов). Пустой или
   слишком короткий отзыв не отправляется — показывается подсказка.
4. **«Прикрепить отзыв»** → окно «Отзыв проверяется. Награда скоро будет у вас».
5. После этого в карточке задания статус меняется на **«Отзыв на проверке»**, а сам текст отзыва
   сохраняется под заданием. Кнопка «Выполнил» больше не показывается.

Состояние задания (`stage: 'progress' | 'under-review'`, текст отзыва, дата) сохраняется в
`localStorage` под ключом `alfaTasks.activeTasks`, поэтому статус переживает перезапуск приложения.
Отзыв экранируется (`escapeHTML`) и выводится как текст, а не как HTML.

## Экран «Перед началом» и логотип (обновление от 17.09.2026, `?v=20260917-12`)

- **Вступление задания «Отзывы»** (открывается по нажатию на карточку) обновлено в
  `renderIntro()` (`app.js`). Текст разбит на два абзаца: «Мы платим за вашу обратную связь
  касаемо нашего сервиса, в который входит процесс доставки продукта и сопровождение клиента
  на всех начальных этапах.» и выделенная красная строка «Оставьте отзыв и заберите награду».
  Ниже — пометка, что **один человек может получить награду сразу за два варианта**.
  Стили блока — классы `.intro-card`, `.intro-copy`, `.intro-lead` в конце `styles.css`.
- **У логотипа убран серый фон.** Причина: у кнопки `.header-brand` в шапке не задан `background`,
  и браузер подкладывал под неё стандартный серый фон кнопки. Общий сброс кнопок теперь
  обнуляет фон и паддинги (`button { appearance:none; padding:0; background:none; }`),
  а у самой шапки явно `background: transparent`. Дополнительно добавлен `favicon.svg`
  с прозрачным фоном (красный знак «А»).
- **Лёгкая полировка UI под стиль Альфа-Банка:** градиент и внутренняя подсветка у основных
  кнопок, каскадная анимация блоков при переходах (`.view-enter > *` со ступенчатой задержкой),
  «прижатие» карточек при тапе, сдвиг стрелок при наведении, бейдж `18+`, акцентная полоса
  у заметок `.info-note`, `text-wrap: balance` у заголовков, `tabular-nums` у сумм.
- Версия кэш-бастинга поднята до `?v=20260917-12` у всех ассетов в `index.html`.

## Автоматическая защита (CI)

`.github/workflows/checks.yml` на каждый пуш и PR в `main` прогоняет:

- `npm run check:syntax` — синтаксис всех `.js`/`.mjs` (именно этот шаг ловит описанную выше ошибку);
- валидность `render.yaml`;
- `npm test` — смоук-тест интерфейса: поднимает настоящие `index.html` + `app.js` + `profile-fix.js`
  в jsdom и прокликивает все экраны (гейт → отказ/доступ → задания → награды → возрастная проверка →
  инструкция → личный кабинет), проверяет тексты обеих инструкций и весь диалог сдачи задания
  («Выполнил» → вопрос про карту → отказ/согласие → отзыв → «Отзыв проверяется» → статус карточки),
  плюс сценарии профиля Telegram, восстановления сессии, заблокированного `localStorage`
  и аварийного экрана;
- `npm run test:http` — поднимает `server.js` и проверяет коды ответов, `Content-Type`,
  заголовки кэширования, SPA-fallback, защиту от выхода за корень сайта, `HEAD`/`POST`.

Локально всё сразу:

```bash
npm i --no-save jsdom   # нужен только для смоук-теста интерфейса
npm run check
```

## Деплой

Сайт полностью статический (HTML + CSS + JS) и разворачивается как **Static Site** в Render —
такой сервис не засыпает (в отличие от бесплатного Web Service) и раздаётся с CDN.

Через Blueprint (рекомендуется): **New → Blueprint** → выбрать этот репозиторий — `render.yaml`
создаст Static Site сам.

Вручную: **New → Static Site** → репозиторий `karalik19-a11y/alfa` →
**Build Command:** `true`, **Publish Directory:** `.`

URL в BotFather менять не нужно — адрес сайта не изменился.

Опционально, чтобы сократить время сборки: в настройках сайта добавьте переменную
`SKIP_INSTALL_DEPS=true` (в проекте нет рантайм-зависимостей).

## Запуск локально

Нужен Node.js 18+ (только для удобства локального сервера).

```bash
npm start
```

Откройте http://localhost:10000

## Где менять контент

- `app.js` — тексты экранов, ссылки и логика переходов.
- `styles.css` — визуальная система, мобильная адаптация, анимации и красно-белая тема.
- Ссылки и подписи двух вариантов награды — объект `rewards` в начале `app.js`.
- Тексты пошаговых инструкций — объект `instructionPlans` сразу под `rewards`
  (`small` — вариант 01 «дебетовая карта», `large` — вариант 02 «кредитная карта»).
- Тексты окон «Выполнил → отзыв → проверка» — функция `renderModal()` в `app.js`.

В Telegram WebApp профиль берётся из `Telegram.WebApp.initDataUnsafe.user`.
При открытии в обычном браузере используется демо-профиль.

> После правок `app.js`/`styles.css` поднимайте версию в `index.html` (`?v=…`) —
> ассеты закэшированы как `immutable`, и без новой версии изменения не доедут до пользователей.
