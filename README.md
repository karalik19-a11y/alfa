# Альфа tasks

Мобильный лендинг в формате Telegram Mini App: проверка участия, витрина заданий, выбор уровня награды, пошаговая инструкция и личный кабинет с заданиями в процессе.

**Рабочий URL:** https://alfa-w3ll.onrender.com

## Почему сайт «не открывался»

Настоящая причина была не в хостинге, а в коде: в `app.js` (строка 44, функция `renderActiveTask`)
**не была закрыта шаблонная строка** — пропущена обратная кавычка перед `;}`.

Из-за этого браузер не мог разобрать модуль целиком:

```
SyntaxError: Unexpected token 'class'   (app.js:45)
```

`app.js` подключён как `<script type="module">`, поэтому при ошибке разбора не выполняется
**ничего** — `<div id="app">` остаётся пустым, и пользователь видит пустой белый экран
в Telegram и в обычном браузере. Ошибка не видна без консоли разработчика, поэтому выглядело,
будто «сайт не работает».

Проверить одной командой:

```bash
node --check app.js
```

## Что исправлено

1. **Закрыта шаблонная строка в `renderActiveTask`** — приложение снова разбирается и рендерится.
2. **Версия кэш-бастинга поднята до `?v=20260917-9`.** Это обязательно: `app.js` отдаётся с
   `Cache-Control: immutable, max-age=31536000`, поэтому у тех, кто уже открывал сайт,
   сломанный файл лежит в кэше на год. Новый URL заставляет его скачать заново.
3. **Страховка от белого экрана** (двухуровневая):
   - `index.html` — watchdog: если `app.js` не загрузился или упал при разборе, вместо пустой
     страницы показывается понятное сообщение с кнопкой «Обновить страницу»;
   - `app.js` — `render()` обёрнут в `try/catch`, при сбое рисуется аварийный экран с текстом ошибки;
   - добавлен `<noscript>`-вариант страницы.
4. **Устойчивость к злому окружению:** обращение к `localStorage` при инициализации больше не
   может уронить приложение (в некоторых WebView хранилище заблокировано и бросает `SecurityError`),
   тост не падает при отсутствии элемента.
5. **Имя пользователя в шапке** теперь полное (`getDisplayName`), как в карточке профиля —
   раньше в шапке было только имя, и через ~250 мс текст «прыгал» на полное имя.
6. **`render.yaml`:** добавлено правило `Cache-Control: no-cache` для корневого пути `/`
   (запрос к главной идёт как `/`, а не `/index.html`) — иначе `index.html` может закэшироваться,
   и пользователи останутся на старых ссылках `?v=…`.
7. **Удалён пустой файл `.github/workflows/keep-alive.yml`** (0 байт — GitHub считает такой
   workflow невалидным) и добавлен нормальный CI.

## Автоматическая защита (CI)

`.github/workflows/checks.yml` на каждый пуш и PR в `main` прогоняет:

- `npm run check:syntax` — синтаксис всех `.js`/`.mjs` (именно этот шаг ловит описанную выше ошибку);
- валидность `render.yaml`;
- `npm test` — смоук-тест интерфейса: поднимает настоящие `index.html` + `app.js` + `profile-fix.js`
  в jsdom и прокликивает все экраны (гейт → отказ/доступ → задания → награды → возрастная проверка →
  инструкция → личный кабинет), плюс сценарии профиля Telegram, восстановления сессии,
  заблокированного `localStorage` и аварийного экрана;
- `npm run test:http` — поднимает `server.js` и проверяет коды ответов, `Content-Type`,
  заголовки кэширования, SPA-fallback, защиту от выхода за корень сайта, `HEAD`/`POST`.

Локально всё сразу:

```bash
npm i --no-save jsdom   # нужен только для смоук-теста интерфейса
npm run check
```

## Деплой

Сайт полностью статический (HTML + CSS + JS) и разворачивается как **Static Site** в Render —
такой сервис не засыпает (в отличие от бесплатного Web Service) и раздаётся с CDN.

Через Blueprint (рекомендуется): **New → Blueprint** → выбрать этот репозиторий — `render.yaml`
создаст Static Site сам.

Вручную: **New → Static Site** → репозиторий `karalik19-a11y/alfa` →
**Build Command:** `true`, **Publish Directory:** `.`

URL в BotFather менять не нужно — адрес сайта не изменился.

Опционально, чтобы сократить время сборки: в настройках сайта добавьте переменную
`SKIP_INSTALL_DEPS=true` (в проекте нет рантайм-зависимостей).

## Запуск локально

Нужен Node.js 18+ (только для удобства локального сервера).

```bash
npm start
```

Откройте http://localhost:10000

## Где менять контент

- `app.js` — тексты экранов, ссылки и логика переходов.
- `styles.css` — визуальная система, мобильная адаптация, анимации и красно-белая тема.
- Ссылки для двух вариантов награды находятся в объекте `rewards` в начале `app.js`.

В Telegram WebApp профиль берётся из `Telegram.WebApp.initDataUnsafe.user`.
При открытии в обычном браузере используется демо-профиль.

> После правок `app.js`/`styles.css` поднимайте версию в `index.html` (`?v=…`) —
> ассеты закэшированы как `immutable`, и без новой версии изменения не доедут до пользователей.
